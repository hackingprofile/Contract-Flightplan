# Threat model

Assets: OpenAPI contracts, fixture examples, mapping rules, approval records, HTML/JSON/SARIF reports, generated test suites, CI definitions.

| Threat | Mitigation | Test owner |
| --- | --- | --- |
| Unapproved proposal execution | `verify` rejects `kind=proposal` | `unapproved_proposal_cannot_verify`, CLI e2e |
| Injected approval on a proposal | proposal loader rejects `approval` | `injected_approval_is_rejected` |
| Ill-typed rule approved (string into integer, bad default, non-exhaustive enum) | `typecheck` blocks `approve`; `review` exits 3 with diagnostics | `typecheck::tests::*`, `review_writes_diagnostics_and_exits_three_for_ill_typed_proposal` |
| Stale contract/rule/fixture | digest recompute | `stale_rule_or_fixture_or_contract_is_rejected` |
| A file swapped while approve runs is bound although the review record and type-check saw other content | every input is read once; the digests bound are those of the bytes parsed and checked; a catalog or fixture that differs from the folder digest is refused | `a_contract_swapped_during_approve_is_never_bound_unseen` |
| Remote `$ref` exfiltration | load rejects protocol refs | `unsupported_and_ambiguous_and_refs`, CLI exit 2 |
| Path traversal `$ref` | `..` rejected | same |
| Recursive schema hang | cycle → unsupported | same |
| Oversize/deep input | bounds | `resource_bound_rejects_oversize_input` |
| A YAML contract with deep flow nesting (`[[[[...`) inside the size bound takes minutes to parse | a streaming pre-pass with the parser's own tokenizer stops at 33 levels of nesting before the full parse (`depth`, exit 3) | `deep_yaml_flow_nesting_is_refused_quickly`, `nesting_is_measured_in_flow_and_block_style`, `flow_heavy_yaml_within_the_depth_bound_still_compares` |
| A device, FIFO or a symlink to one (`/dev/zero`, a pipe) as any input exhausts memory or blocks, also when swapped in between a type check and the open; a refused proposal of any size is copied into quarantine | every input is read through one reader: only regular files, decided by the open handle's type (opened without blocking on Unix, so a FIFO swapped in is refused at once), at most 1 MiB, enforced while reading; quarantine copies only what that reader returns | `every_input_refuses_a_device_file`, `quarantine_does_not_copy_an_input_beyond_the_size_bound`, `bounded_read_stops_on_an_endless_stream`, `endless_devices_are_refused_without_reading`, `a_fifo_is_refused_without_blocking`, `a_symlink_to_a_device_is_refused`, `a_fifo_swapped_in_after_the_type_check_never_hangs` (the last four Linux and macOS only) |
| A small contract whose `$ref`s fan out exhausts memory or time | each contract's `$ref` expansion is charged to a budget (100,000 schema nodes, about 64 MiB copied); beyond it the command stops with `schema_nodes` or `schema_bytes` (exit 3); notes are de-duplicated with a set and one diff lists at most 100,000 entries | `ref_fanout_beyond_the_node_budget_is_refused_with_exit_3`, `ref_fanout_beyond_the_byte_budget_is_refused_with_exit_3`, `two_wide_sixteen_deep_ref_fanout_is_refused_quickly`, `wide_three_level_ref_fanout_is_refused_without_exhausting_memory` |
| HTML script injection | escape + CSP | `html_escapes_script_fixture`, visual DOM dump |
| Rename / split / merge overwrite | collision error; duplicate targets rejected at decode and runtime | `split_duplicate_targets_collide`, `duplicate_split_targets_are_rejected_at_decode` |
| Default replacing null | explicit_null | mapping unit tests |
| Unknown enum guessed | unknown_enum / fail policy | mapping + enum pack |
| Unknown mapping op | rejected | `unknown_mapping_operation_is_rejected` |
| Declared lossiness hides real data loss | lossiness computed from execution; witness compares declared vs observed | `lossiness_is_computed_not_declared`, `witness_is_computed_from_execution`, `lossiness_witness_reports_declaration_mismatch` |
| Silent verify failure (no report on exit 1) | `verify` always writes `--out`; `--sarif` requires the report's own verification run (`--migration`, `--proposal`, `--fixtures`) | `verify_failure_writes_report_and_sarif_carries_rule_and_region` |
| An empty catalog, or one that skips a rule, verifies as "stable, 0/0" | approve and verify require at least one fixture and a fixture for every rule; a run with no outcomes is never stable | `an_empty_catalog_is_refused_at_approve`, `a_rule_without_a_fixture_is_refused_at_approve`, `verify_refuses_a_catalog_emptied_after_approval` |
| A hand-edited verify result steers the report: a green verdict for a failed run (an edited `actual`, a deleted failing outcome, edited flags), another pack's result, or an attacker URL copied into SARIF | `report` never reads a verdict from a file: with `--migration` it requires `--proposal` and `--fixtures` and re-runs verification itself; the verdict, counts, failing list and SARIF come only from that fresh run, and a `--verify` file that differs from it in any way (ids, count, expect, actual, flags, path, approval) is refused with exit 3 before anything is written; SARIF URIs are percent-encoded relative fixture paths | `report_refuses_a_verify_file_whose_actual_was_edited`, `report_refuses_a_verify_file_with_a_deleted_outcome`, `report_takes_the_verdict_from_a_fresh_run`, `report_with_a_migration_but_no_fixtures_is_refused`, `report_refuses_a_verify_result_with_edited_flags`, `report_refuses_a_verify_result_from_another_pack`, `report_refuses_an_outcome_path_that_is_not_a_bound_fixture`, `sarif_uri_is_a_percent_encoded_relative_fixture_path` |
| Local path disclosure in artifacts | `parse::portable_path` reduces absolute paths to file names | `absolute_paths_are_reduced_to_file_names`, CLI e2e |
| An output overwrites the command's own input (`verify --out` the migration, `compare --out` the contract, or a file inside `--fixtures`, `--packs` or `--pack`: the catalog, a bound fixture, a new file) or is written through a link to another file | output paths are checked against every input, every input folder (an output resolved anywhere inside one, through missing subfolders too, is refused) and each other before anything runs; outputs are written to a temporary file and renamed, and a link at the output path is refused | `verify_refuses_to_write_its_report_over_the_migration`, `compare_refuses_to_write_over_its_source`, `verify_refuses_outputs_inside_its_fixtures_folder`, `approve_report_and_guide_refuse_outputs_inside_the_fixtures_folder`, `corpus_and_generate_refuse_outputs_inside_their_pack_folders`, `report_refuses_two_outputs_at_one_path`, `outputs_are_not_written_through_a_link` (needs a host that can create file symlinks) |
| An output replaces a device node, FIFO or socket (`--out /dev/null` as root replaced the system device with a JSON file; as a normal user it failed) | a character device or FIFO at the output path is written to directly, never renamed over, with the open handle's type checked again; Windows `NUL` likewise; block devices, sockets, other special files and other Windows devices are refused (exit 3) | `dev_null_as_out_still_works_and_stays_a_device`, `a_fifo_as_out_stays_a_fifo_and_receives_the_output`, `a_socket_as_out_is_refused_and_stays_a_socket`, `a_block_device_as_out_is_refused_and_stays_a_device` (Unix; the block-device case needs root on Linux), `nul_as_out_works_on_windows`, `other_windows_devices_as_out_are_refused` |
| Stale published schema accepts what the interpreter rejects | shipped packs, CLI outputs and negative cases validated with `jsonschema` | `tests/schema_contract.rs` |
| Workflow expression injection / unpinned actions | `run:` blocks take values via `env:`; every action pinned to a 40-hex SHA; read-only permissions | `tests/workflows.rs` |
| Breaking change hidden below the top level | recursive diff over `properties` and `items` through local `$ref`s; every change has an RFC 6901 pointer and a class; anything unclassified is `unknown`, never "no change" | `nested_property_type_change_is_detected_with_pointer`, `unclassified_nested_keyword_change_is_unknown_not_silent` |
| Fixture catalog path leaves the fixtures folder (traversal, absolute or drive path) and leaks a file into reports | catalog paths accept only normal name components; the canonical file must sit under the canonical fixtures folder, at approve and at verify | `catalog_path_with_parent_traversal_is_refused_at_verify_and_leaks_nothing`, `absolute_and_drive_relative_catalog_paths_are_refused_at_approve` |
| A catalog id used as a file name makes a generated suite write outside its temporary folder (`../`, absolute ids) | catalog ids are plain names from a safe set, checked when the catalog is read; generated suites name output files by position | `catalog_ids_outside_the_safe_set_are_refused`, `generated_node_suite_cannot_write_outside_its_folder`, `generated_suites_name_output_files_by_position` |
| Two catalog items share one id, so reports, SARIF and generated suites cannot tell them apart | a duplicate id is refused when the catalog is read (exit 3) | `duplicate_catalog_ids_are_refused` |
| A file outside the folder changes after approval and still passes | only bound files can be read; verify compares the digest of the bytes it reads | `file_outside_the_fixtures_folder_changed_after_approval_cannot_pass_verify` |
| A junction or symlink in the fixtures folder escapes the digests | links and reparse points are refused by the digest walker and the reader | `junction_inside_the_fixtures_folder_is_refused_at_approve`, `junction_added_after_approval_is_refused_at_verify` |
| A file name containing a backslash (legal on Linux and macOS) reads as a nested path and shares its digest key, leaving one file unbound | digest keys are built from path components joined with `/`; a name with `\` or a non-UTF-8 name is refused, and two files with one key are refused | `fixture_digest_keys_are_unambiguous`, `a_backslash_file_name_cannot_share_a_digest_key` (Linux and macOS only) |
| Reviewer name or note forges the verdict in Markdown or the CI job summary | untrusted text is neutralized (controls shown, `<` `>` `&` as entities, Markdown punctuation escaped) | `job_summary_counts_failures_and_cannot_be_forged_by_the_reviewer`, `markdown_report_neutralizes_untrusted_text` |
| Zero-width or bidi characters make two different reviewer names (or ids, notes) render identically in a report | every Unicode format character, variation selector, U+034F and the Hangul fillers are shown as escapes in HTML, Markdown, the job summary and the terminal | `invisible_and_bidi_characters_are_shown_as_escapes` |
| Untrusted text on stderr or in the guide redraws the terminal (escape sequences) or forges GitHub Actions workflow commands (a line starting `::error`, `::add-mask::`) | every error, usage error and guide line is printed through one function that shows control characters as escapes and breaks up a leading `::` | `error_messages_show_control_characters_as_escapes`, `workflow_commands_cannot_start_a_line_on_stderr`, `usage_errors_show_control_characters_as_escapes`, `guide_output_shows_control_characters_as_escapes`, `terminal_text_escapes_controls_and_breaks_up_workflow_commands` |
| A report hides the run's verdict | HTML, Markdown and job summary open with stable yes/no, N of M passed and the failing ids | `html_report_opens_with_the_verdict`, `markdown_lists_failures` |
| Duplicate JSON or YAML keys let the last value win silently | strict JSON and YAML readers for proposals, migrations, catalogs, fixtures, review records and contracts: a duplicate key is a parse error naming the key and its pointer | `duplicate_key_in_proposal_is_a_parse_error_naming_the_key`, `duplicate_key_in_migration_is_refused_at_verify`, `duplicate_key_in_a_json_contract_is_a_parse_error_naming_key_and_pointer`, `duplicate_key_in_a_yaml_contract_is_a_parse_error_naming_key_and_pointer` |
| Unknown fields slip into proposals, migrations, catalogs or review records | unknown fields and rule parameters are refused, matching the schemas | `unknown_top_level_proposal_field_is_refused`, `review_record_with_duplicate_key_or_unknown_field_is_refused` |
| A moved operation reads as removed plus added | leftovers paired by `operationId` into `moved_operations` and still diffed | `moved_operation_is_classified_not_added_removed` |
| Pointers that do not resolve | every pointer segment RFC 6901-escaped | `pointers_are_rfc6901_escaped` |
| Notes repeated or mislabelled | each unsupported note emitted once with its construct and location | `recursive_reference_note_is_emitted_once_with_its_location` |
| Removals derived from a body the tool cannot read | an unreadable root derives no per-name lists; the body is `unknown` | `allof_body_reports_unknown_and_derives_no_removals` |
| Imported oasdiff severity dropped | `level`, `operation`, `path` kept; level mapped to a class | `oasdiff_array_shape_is_ingested_with_level` |
| Public docs disagree on exit codes | README and CLI tables checked identical | `readme_exit_codes_match_the_cli_doc` |
| A closed or full standard output crashes the tool with an undocumented exit code (101) | output is written with checked writes; a failure is an I/O error, exit 3; a closed stderr is ignored | `a_closed_stdout_is_an_error_not_a_panic`, `a_full_disk_on_stdout_is_an_error_not_a_panic` (Linux only) |
| Approval without review, or an edited approval history | `approve --review` binds the review record; history hash chain checked at verify and by `history --verify-chain`; local records, not signatures | `approve_without_review_record_fails`, `edited_reviewer_or_emptied_history_is_refused_at_verify`, `history_chain_detects_removed_event` |
| A superseded migration, or an archive copy edited back to `approved`, still verifies | verify refuses a migration that a migration in the same folder supersedes, or whose history an archive copy there continues; local evidence only, documented | `a_superseded_migration_is_refused_while_its_successor_or_archive_is_present`, `an_archive_copy_edited_back_to_approved_is_refused` |
| An approved migration's rules or fixtures edited and their digests recomputed inside the file | the `approved` event commits to every bound digest, so the chain breaks; `verify --proposal` runs only rules equal to the reviewed proposal's, so a forger who recomputes every digest must also change the reviewed proposal file; tamper-evident local records, not signatures | `edited_rules_with_a_recomputed_rules_digest_break_the_history_chain`, `edited_fixture_with_recomputed_fixture_digests_breaks_the_history_chain`, `migration_rules_that_differ_from_the_reviewed_proposal_are_refused_at_verify`, `verify_refuses_a_proposal_other_than_the_approved_one` |
| Approve binds a fixture verify cannot read | every catalogued fixture must be UTF-8 JSON before any digest is bound | `approve_refuses_a_utf16_fixture_and_names_it` |
| A corpus "seed" that changes nothing | a real u64 seed drives the fixture generator; the same seed gives the same report | `corpus_two_runs_identical`, `fixture_generator_uses_the_seed` |
| A malformed proposal from a provider is lost or accepted | every provider response passes the file-proposal checks; `--quarantine` keeps refused input with its diagnostics | `mock_provider_contract_roundtrip`, `malformed_proposal_is_quarantined_with_diagnostics` |
| Declared schema constraints silently ignored | bounds, `pattern` and validated formats enforced; an unevaluable pattern is unsupported | `schema_validation_enforces_numeric_and_string_bounds`, `format_date_time_and_uuid_are_validated` |
| The validator accepts values other JSON Schema validators refuse (Unicode digits for `\d`, `[1, 1.0]` as unique, invisible characters in an email, a leap second at any minute) or refuses ones they accept (`1.0` as integer or enum value) | ECMA-262 classes, numeric equality and the format rules are matched; each remaining difference is listed in `docs/supported-matrix.md` | `validator_matches_json_schema_where_it_differed` |
| A value beyond `maximum`/`minimum` passes because both were compared as doubles (2^53 and above, near the 64-bit limits) | bounds are kept as written and compared exactly: integers as integers, an integer against a fraction by its floor | `numeric_bounds_are_compared_exactly` |
| A small fixture under a costly `pattern` takes minutes (the pattern compiled for every string) | each distinct pattern compiles once per contract within 512 KiB (larger is unsupported, exit 2); at most 256 distinct patterns (`patterns`, exit 3) | `a_pattern_is_compiled_once_not_per_string`, `a_pattern_beyond_the_compile_limit_is_unsupported_quickly`, `distinct_patterns_beyond_the_bound_are_refused` |
| Provider outbound | hosted modes `not_enabled`; preview `blocked`; redaction shows no scalar values | `provider_preview_is_blocked`, `hosted_providers_are_preview_only`, `provider_preview_select_shows_redacted_shape_and_stays_blocked` |

Out of scope: remote identity for reviewers, signatures over migration files or the release tree (the history chain, the reviewed-proposal check and the checksums are tamper-evident: they catch edits that do not also change every bound file and digest, nothing more; signing is not implemented). The workflows are linted locally; their runs on hosted CI are recorded in `docs/HOST-MATRIX.md`.
